# Implementation Plan - CHAMP (Campus Healthcare Accessibility & Management Platform) Backend API

Build a production-grade, modular RESTful backend API for CHAMP using Node.js, Express, Prisma ORM, and SQLite.

## User Review Required

> [!NOTE]
> SQLite is used for zero-configuration, lightning-fast local development with Prisma.
> The server will be configured to run on Port `5000` with comprehensive error handling, input validation, and transaction-safe queue management.

## Database Schema Design (`prisma/schema.prisma`)

- **User**: `id`, `name`, `email`, `role` (STUDENT | DOCTOR | PHARMACIST | COUNSELOR), `hostelBlock`, `phone`, `createdAt`, `updatedAt`
- **Doctor**: `id`, `name`, `specialty`, `availabilityStatus` (AVAILABLE | BUSY | OFFLINE), `currentQueueLength`, `roomNumber`, `createdAt`, `updatedAt`
- **Appointment**: `id`, `studentId`, `doctorId`, `status` (QUEUED | IN_PROGRESS | COMPLETED | CANCELLED), `queueNumber`, `reason`, `createdAt`, `updatedAt`
- **Prescription**: `id`, `studentId`, `imageBase64OrUrl`, `status` (PENDING | VERIFIED | DISPATCHED), `hostelDeliveryAddress`, `notes`, `createdAt`, `updatedAt`
- **HealthAlert**: `id`, `title`, `message`, `alertType` (EPIDEMIC | HEATWAVE | VACCINATION | GENERAL), `severity` (LOW | MEDIUM | HIGH | CRITICAL), `isActive`, `timestamp`
- **EmergencyDispatch**: `id`, `studentId` (optional), `studentName`, `contactNumber`, `location`, `details`, `status` (DISPATCHED | RESPONDING | RESOLVED), `timestamp`

## Endpoints Implementation

1. **Doctors (`/api/doctors`)**:
   - `GET /api/doctors`: Fetch all doctors with live availability status and dynamic queue counts.
   - `POST /api/doctors`: Register or update doctor profile and status.

2. **Appointments (`/api/appointments`)**:
   - `POST /api/appointments`: Transactional booking that calculates the next sequential `queueNumber` for the doctor and increments `currentQueueLength`.
   - `GET /api/appointments/queue/:id`: Real-time queue check showing appointment details, doctor info, current serving queue number, and estimated wait position.
   - `GET /api/appointments`: List appointments with filters (`studentId`, `doctorId`, `status`).
   - `PATCH /api/appointments/:id/status`: Update status (e.g. advance queue to IN_PROGRESS or COMPLETED, decrementing queue count).

3. **Prescriptions (`/api/prescriptions`)**:
   - `POST /api/prescriptions`: Submit prescription image/URL, delivery hostel room, notes.
   - `GET /api/prescriptions`: List prescriptions with filter by status or student.
   - `PATCH /api/prescriptions/:id/status`: Pharmacist verification and dispatch workflow.

4. **Health Alerts (`/api/alerts`)**:
   - `GET /api/alerts`: Get active campus alerts sorted by timestamp descending.
   - `POST /api/alerts`: Broadcast new health alert.

5. **Emergency Dispatch (`/api/emergency`)**:
   - `POST /api/emergency`: Instant priority emergency dispatch with student telemetry, GPS/hostel coordinates, and emergency notes.
   - `GET /api/emergency`: Real-time emergency feed for campus ambulance / response teams.
   - `PATCH /api/emergency/:id/status`: Update status to RESPONDING or RESOLVED.
